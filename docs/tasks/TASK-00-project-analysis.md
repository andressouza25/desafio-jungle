# TASK-00 — Project Analysis

## Objective

Turn the specifications, architecture and supplied assets into a concise implementation plan before application code is introduced.

## References

- `README.md`
- `MASTER_SPEC.md`
- `ARCHITECTURE.md`
- `DESIGN_SYSTEM.md`
- `AGENTS.md`
- `TASKS.md`

## Skills

- `pixijs` — use only to validate PixiJS-specific architectural decisions. Do not implement gameplay during this task.

## Scope

- Inspect the repository structure, official challenge, reference screens and supplied visual/audio assets.
- Validate the proposed architecture and React/PixiJS boundaries.
- Define the minimum tooling, dependencies and application structure needed for implementation.
- Map simulation, input, rendering, data, persistence and testing responsibilities.
- Identify task dependencies, implementation risks and unresolved decisions.
- Recommend how `original-challenge/` should be handled before final delivery.
- Report necessary architectural changes instead of introducing them without justification.

## Out of Scope

- Installing dependencies or bootstrapping the application.
- Implementing screens, gameplay, APIs or tests.
- Modifying supplied assets.
- Starting TASK-01 or any later task.
- Introducing architecture not required by the challenge.

## Acceptance Criteria

- Mandatory technologies and major requirement areas have clear responsibilities.
- React, game simulation and PixiJS rendering boundaries are explicit.
- Supplied assets and reference screens have been inspected.
- Proposed tooling and dependencies have clear purposes.
- Task ordering and dependencies are coherent.
- Risks and unresolved decisions are identified.
- No implementation work has started.

## Validation

- Cross-check the plan against the official challenge and `MASTER_SPEC.md`.
- Confirm the roadmap covers all mandatory requirement areas.
- Confirm the proposed approach does not conflict with `ARCHITECTURE.md`.
- Confirm no application or configuration files were introduced.
